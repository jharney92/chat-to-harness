Phase 3: The stack / Module 11

Clerk

Add sign-in so each person sees only their own ideas, and learn the one check that separates a secure app from one that only looks secure.

60 minutesFree

What it is

Right now anyone who finds your address can see and add ideas. Sign-in fixes that. The general word is authentication, usually shortened to auth: proving who someone is. Its partner is authorization: deciding what that person is allowed to see and do.

Building sign-in yourself means storing passwords, handling resets, blocking attackers and keeping up with security problems for as long as the app exists. Nobody should do that for a side project. Clerk is a service that provides the sign-in screens and the user accounts, and hands your app one reliable fact: who this is.

Cost: Clerk is free for up to 50,000 monthly returning users per app, with no credit card. See the pricing page.

The idea that matters most

Clerk gives every person who signs up a unique ID. Your ideas table gets a new column to hold it. From then on, every time the app reads or writes ideas, it includes that ID: show me the ideas where the owner is this person.

The most common serious bug in beginner apps
The sign-in screen works, so the app feels secure. But one query forgets to filter by owner, and every user can see every other user's data. Sign-in proves who someone is. Only your queries decide what they see.

Set it up

1
Create your Clerk account and application

Sign up at clerk.com. Create an application named Campaign Notes and choose email and Google as sign-in options.

2
Add the two keys to your secrets file

Clerk shows two keys. Put both in .env.local yourself.

In the file
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=paste-here
CLERK_SECRET_KEY=paste-here

This pair is the clearest example of Module 9's rule. The publishable key is meant for the browser, so it carries the public prefix. The secret key never leaves the server.

3
Have the agent add sign-in
Type this to Claude
Add Clerk sign-in to this app. Read Clerk's current Next.js App Router quickstart first and follow it.
Show a sign-in button when signed out and a user menu when signed in.
Only signed-in users can see or add ideas.
Add an owner column to the ideas table. Every read and write must filter by the signed-in user.
I can sign up with a second email address and see an empty list.
4
Run the test that matters

Sign up and add two ideas. Sign out. Sign up again with a different email address.

You should see: an empty list. If you see the first account's ideas, stop and tell the agent exactly that.
5
Make it work live
Type this
vercel env add NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY
vercel env add CLERK_SECRET_KEY
Type this to Claude
Commit and push.

Repeat the two-account test on your live address.

Ask the agent to check its own work

Because the owner filter is easy to miss, have a second look taken by something that did not write the code.

Type this to Claude
Review every database query in this project. List each one and say whether it filters by the signed-in user.
Flag any that do not.

This is a small version of the review role from Module 2. In Phase 4 a separate reviewing agent does this automatically.

Going fully live later

Clerk starts every application in a development mode, which is right for learning and for showing friends. Opening an app to the public means switching to a production setup, which Clerk's documentation walks through. You do not need it for this guide.

Other ways to do this

The concepts above are the same whichever you choose.

Alternative
Supabase
A database and sign-in from one company, in one account. Fewer moving parts, and a common choice for first projects.
Alternative
Sign-in from your database host
Neon and others now offer built-in user accounts alongside the database. Worth a look when you start a new project.

When something goes wrong

What you see
What it means
What to do
An error about a missing publishable key
The app cannot find the Clerk keys.
Check both lines in .env.local and restart the app.
Sign-in works locally and fails live
The keys are not in Vercel, or you have not redeployed.
Add both with vercel env add and redeploy.
The page reloads in a loop
The sign-in page itself is being protected.
Tell Claude the sign-in and sign-up pages must be public.
A second account can see the first account's ideas
A query is missing the owner filter.
Stop. Run the review prompt above and fix every flagged query before doing anything else.
Ideas added before sign-in have disappeared
They have no owner, so no user's filter matches them.
Expected. Delete them in Neon or ask Claude to assign them to your account.
