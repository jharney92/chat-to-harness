Two runbooks

A plain text file the agent reads at the start of every session.

GLOBAL

About you

Who you are, how you want an agent to think, what it must never do anywhere.

PROJECT

About this project

What it is, its commands, how it ships, and what looks wrong but is intentional.

Notes: Module 18. One file named AGENTS.md serves every agent tool. A one-line CLAUDE.md imports it. Every line costs attention, so the test is whether the agent would do worse without it.
Slide 4 of 14

Three habits that make a runbook trustworthy

1

Cite the source

Each line names the file it came from. A line with nothing to cite probably should not be there.

2

Say what is intentional

Agents fix things. Mark anything that looks like a bug but is deliberate.

3

Date your claims

Not “all tests pass.” The last recorded result, with its date.

Notes: Module 18. These come straight from the real runbooks. The second habit prevents an agent from helpfully repairing a design decision.

Slide 7 of 14

The team

Five roles. Each is one file, with one job and a clean desk.

PLANS

architect

Writes the plan. No code.

BUILDS

developer

Smallest change. Runs every test.

CHECKS

reviewer

One word: merge or fix.

FINDS

debugger

Evidence first. Cleans up.

WRITES

writer

Documents what exists.

Notes: Module 19. The agent that built something is the worst one to judge it. A reviewer that never saw the work being made reads it fresh. Video 7.

Slide 10 of 14

Four tiers

TIER 1

Just do it

Tell me after. Reversible, reviewed, tested.

TIER 2

Veto window

Doing this at 3:00 unless you say stop.

TIER 3

A real gate

Money, real people, anything irreversible.

TIER 4

Decide and flag

Everything else. Pick, ship, log it.

Notes: Module 20. Tier 4 is what makes it move. Without it the agent asks about everything and the student becomes the bottleneck.

Every feature goes through the same six steps.

1

Scope

A plan.

2

Build

In its own copy.

3

Review

Once.

4

Fix

Must-fix only.

5

Merge

Undo written.

6

Check live

Someone uses it.

Notes: Module 20. Two rules inside it: nothing is done until it has been exercised, and one review then ship. Merged is not finished.
Slide 12 of 14

What things cost, and why

Route models by the cost of a mistake. Put the cost guard on loops.

1

Short sessions

A long conversation rereads its whole history on every turn. End, hand off, start fresh.

2

Verify elsewhere

Test runs and log reading go to a subagent that returns a verdict.

3

Spend where it hurts

Fast model for reading. Strongest for planning and risky reviews.

Notes: Module 20. The author measured it: the expensive thing was one long session, not the choice of model.
Slide 13 of 14

Finish, don’t fill.

Told to stay busy, agents build infrastructure. Measure finished outcomes, never usage.

Notes: Module 20. The most valuable lesson from running this unattended. It looks like progress and is not.

In class

1

Notes: The second prompt usually yields three: approve the plan, test the preview, say merge. That is the job.
