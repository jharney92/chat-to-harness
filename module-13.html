Command-line tools

Why agents work best through text commands, how to read any command you meet, and how to build one of your own.

50 minutesFree

What it is

A command-line tool, or CLI, is a program you run by typing its name. You have been using them since Module 4: git, gh, brew, npm, vercel, and claude itself.

They matter more for agents than for people. An agent cannot easily click through a website, but it can type a command and read what comes back. Text in, text out. Every service in your stack has a CLI for exactly this reason, and an agent that knows they exist will use them instead of asking you to go click something.

How to read any command

Almost every command has the same four parts.

Tool
gh
Which program to run.
Action
repo create
What you want it to do.
Target
campaign-notes
What to do it to.
Flags
--private --push
Options. They start with dashes and change how it behaves.

Every tool explains itself. Add --help to any command to see its actions and flags. Tell your agent to do the same before it guesses.

Add the database tool

1
Install and sign in
Type this
brew install neonctlnpm install -g neonctl
neon login
neon projects list
You should see: campaign-notes in the list. The install name is neonctl. The command you run is neon.
2
Watch the agent use two tools together
Type this to Claude
Using the Vercel and Neon command-line tools, tell me the status of my latest production deployment
and how many rows are in the ideas table. Show me each command before you run it.

Read the commands as it proposes them. Find the tool, action, target and flags in each.

3
Tell the agent what it has
Type this to Claude
Add a Tools section to the project's agent instructions listing git, gh, vercel and neon.
Say: use these tools directly instead of asking me to click through a dashboard.

Build your own

A CLI is not something only companies make. It is a script with a name and a few actions. When you notice yourself asking the agent for the same thing repeatedly, turn it into a command.

This is how a setup grows from one agent into a factory. The setup behind this guide runs on a handful of home-made commands. One shows the state of every project. One starts a new agent session on a named task. Each began as a request typed once too often.

1
Have the agent build one
Type this to Claude
Build a small command-line tool in this repository called notes-cli.
notes-cli list prints my ideas from the database as a table, newest first.
notes-cli add "title" --client "name" adds one.
It reads DATABASE_URL from the environment and has a --help screen.
I can run notes-cli list in the terminal and see my ideas.
2
Use it
Type this
notes-cli --help
notes-cli list
notes-cli add "Loyalty card relaunch" --client "Second Shift Coffee"
3
Give it to the agent
Type this to Claude
Add notes-cli to the Tools section of the agent instructions, with one line on what it does.

From now on, any agent working in this project can read and add ideas without touching the website.

Claude as a command

Claude Code can run without the conversation. Give it one question with the -p flag and it answers and exits.

Type this
claude -p "summarize the last five commits in plain English"

That makes Claude something other scripts can call. A scheduled job can ask it a question every morning. Module 17 uses this.

These tools act as you

Each CLI is signed in to your account. An agent that can run vercel and gh can deploy, delete and publish with your authority. This is the reason Claude Code's default setting shows you every command before it runs.

If you see
Stop and read, because
rm -rf
It deletes a folder and everything in it, with no Trash.
git push --force
It overwrites history on GitHub.
--prod or --production
It acts on your live site.
DROP or DELETE in SQL
It removes data. Look for the WHERE.
curl ... | bash
It downloads a script and runs it. Fine from an official source you chose. Not from anywhere else.

When something goes wrong

What you see
What it means
What to do
command not found
The tool is not installed, or the terminal predates the install.
Install it, then open a new tab.
Not logged in, or unauthorized
The tool has no saved sign-in, or it expired.
Run the tool's login command, such as neon login or gh auth login.
No project linked
The tool does not know which project this folder belongs to.
Run vercel link or the tool's equivalent from inside the project folder.
It acted on the wrong project
You are signed in to a different account or linked to a different project.
Ask the tool who you are. Most have a whoami or status action.
notes-cli: command not found
Your own tool is not on the terminal's search path yet.
Ask Claude to make it runnable from anywhere and explain what it changed.
