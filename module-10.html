What a database is

So far Campaign Notes forgets everything. The three cards are typed into the code. A database gives the app a memory: a place to store information that survives restarts and is shared by everyone who uses the app.

Picture a spreadsheet that your app can read and write. Each sheet is a table. Each row is one record. Each column is one kind of fact about it.

Postgres, Neon and SQL

Name
What it is
Postgres
The database software. Free, decades old, and the default choice for web apps.
Neon
A company that runs Postgres for you, so you have nothing to install or maintain.
SQL
The language for asking a database questions and giving it instructions.
Cost: Neon's Free plan is $0 with no credit card. Each project gets 1 GB of storage, which is far more than a learning app needs. A free database goes to sleep after five minutes without use and wakes on the next request, so the first click after a quiet spell can be slow. Details on the pricing page.

Enough SQL to read a query

The agent writes SQL. You need to recognize what a statement will do before you approve it.

Statement
What it does
SELECT * FROM ideas;
Read every row and every column from the ideas table.
SELECT title FROM ideas WHERE client = 'Northside Books';
Read only the titles, and only for one client.
SELECT * FROM ideas ORDER BY created_at DESC LIMIT 5;
Read the five newest ideas.
INSERT INTO ideas (title, client) VALUES ('Spring sale', 'Northside Books');
Add a row.
UPDATE ideas SET title = 'Spring clearance' WHERE id = 4;
Change one row.
DELETE FROM ideas WHERE id = 4;
Remove one row.
CREATE TABLE ideas (...);
Make a new table. You will see this once per table.

The one thing to check every time

UPDATE and DELETE without WHERE change every row
The WHERE part chooses which rows are affected. Leave it off and the statement applies to the whole table. When the agent proposes an UPDATE or DELETE, find the WHERE before you approve.
From the runbook behind this guide
Never: destructive database operations, bulk deletes, or migrations without explicit confirmation in-session.

Set it up

1
Create your Neon account and project

Sign up at neon.com with GitHub. Create a project named campaign-notes.

2
Put the connection string in your secrets file

Neon shows a connection string: one long line starting with postgres. It contains the password. Copy it and paste it into .env.local yourself.

In the file
DATABASE_URL=paste-the-whole-string-here

Do not paste it into Claude. The agent will read it from the file by name.

3
Have the agent connect the app
Type this to Claude
Connect this app to the Neon Postgres database in DATABASE_URL, following Neon's current guide for Next.js.
Create an ideas table with id, title, client and created_at.
Replace the example cards with ideas from the database, newest first, and add a form to save a new one.
Show me each SQL statement before you run it.
I can add an idea, refresh the page, and still see it.
4
Look at your data directly

Open the project in Neon and find the SQL editor. Run the first statement from the table above.

You should see: the ideas you added through your app, as rows.
5
Make it work live
Type this
vercel env add DATABASE_URL
Type this to Claude
Commit and push.

Add an idea on your live site. Then check Neon again. The row is there.

Changing a table later

Next week you will want a new column. A change to a table's structure is called a migration, and it is written as a small file so the same change can be applied on your laptop and in production.

Adding a column is safe. Removing or renaming one can destroy data. Treat any migration that drops, renames or rewrites as something that waits for your explicit yes, and ask the agent what would be lost before you give it.

When something goes wrong

What you see
What it means
What to do
Connection refused, or a timeout
The app cannot reach the database.
Check that DATABASE_URL is in .env.local, with nothing cut off, and restart the app.
Password authentication failed
The connection string was copied incompletely or has since been reset.
Copy it again from Neon.
Relation ideas does not exist
The table has not been created in the database the app is talking to.
Ask Claude to check which database it is connected to and create the table there.
It works on my laptop but not live
Vercel does not have the connection string.
Run vercel env add DATABASE_URL and redeploy.
The first load is slow
The free database was asleep.
Normal. It wakes on the first request.
