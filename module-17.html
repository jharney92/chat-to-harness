Local and desktop apps

Tools that live on your own machine: scripts, scheduled jobs, a desktop app and a game.

2 to 3 hoursFree, plus pennies of API credit

Not everything belongs on the internet

Campaign Notes lives on the web because other people sign in to it. Plenty of useful tools have exactly one user: you. They read files on your computer, run on your schedule and never need a sign-in page.

The author's first project was this kind. A script that collected data from a web page, written entirely by ChatGPT, run from a terminal. It is still the right place to start.

A ladder of local tools

Each rung adds a little. Climb only as far as the job needs.

1
A script
One file that does one job when you run it. Rename a folder of images, tidy a spreadsheet, pull numbers from a site.
2
A command
A script with a name and options. You built two: notes-cli and lab.
3
A scheduled job
A script your computer runs by itself at set times.
4
A local web app
Runs at localhost, as Campaign Notes did in Module 7, and simply never gets deployed.
5
A desktop app
Has its own window and icon in the Dock. Opens like any other app.
6
A game
Built in a game engine. Runs on your machine or in a browser.

A database in one file

Local tools still need to remember things. SQLite is a complete database stored as a single file in your project folder. There is no account, no server and no connection string. The SQL you learned in Module 10 works the same way. When a tool is for you alone, start here.

Project A: a job that runs itself

A morning brief. Each weekday your Mac reads your ideas and writes a short file suggesting what to do with each.

1
Have the agent build and schedule it
Type this to Claude
In a new folder ~/Code/morning-brief, write a script that reads my ideas with notes-cli,
asks the Claude API for one suggested next step per idea, and writes a dated text file into ~/Documents/briefs.
Schedule it for 8:00 every weekday using the Mac's built-in scheduler, launchd.
Keep the schedule file in this repository and install it from there.
Each run must write one line to a status file: ok or FAIL, and the time.
Show me how to run it now, how to check the last run, and how to turn it off.
2
Run it by hand first

Use the command the agent gives you. Open the file it wrote. Fix anything you do not like before trusting the schedule.

3
Check on it tomorrow

Look for the new file, and read the status line.

Two things to know. A scheduled job only runs while the computer is awake. And it is the purest case of the rule from Module 12: nobody is watching at 8:00, so the status line is the only way you will learn that it stopped.

The rule behind this setup's health checks
Quiet when all is well. Loud when something is broken.

Project B: a desktop app

A quick-capture pad. Press a keyboard shortcut anywhere, type an idea, press Enter, and it is saved.

1
Create the app
Type this
cd ~/Code
npm init electron-app@latest idea-pad
cd idea-pad
npm start
You should see: an empty window open on your desktop. That is your app. Close it.
2
Have the agent build it out
Type this to Claude
Turn this into a quick-capture app. Read the current Electron documentation first.
A global keyboard shortcut shows a small window with one text box. Enter saves the idea and hides the window.
Store ideas in a local SQLite file. Add a second window that lists them, newest first, with search.
I can press the shortcut from any app, type, press Enter, and find the idea in the list.
3
Make it a real app
Type this
npm run make

This produces an application file you can drag into Applications. For your own use, that is all it takes. Giving it to other people requires signing it with a paid Apple developer account, which is a later problem.

Project C: a game

Godot is a free, open-source game engine. Its projects are made of ordinary text files, which means an agent can read and write them. You describe the game, the agent edits the files, and you press play in Godot's editor to see it.

Brands commission small games regularly, and a playable prototype is a strong thing to bring to a pitch.

1
Install Godot and do the official first game

Download it from godotengine.org. Then follow Your first 2D game, with Claude open in the project folder as your tutor. The tutorial assumes some programming experience. Ask the agent to explain each script as you reach it.

2
Make it yours
Type this to Claude
Reskin this game for Second Shift Coffee. The player is a coffee cup, the enemies are alarm clocks,
and the score is minutes of sleep saved. Change colors and text to match. Do not change how it plays.

Scripts act on your real files

Ask for a dry run first
Before any script renames, moves or deletes files, have it print what it would do without doing it. Read the list. Then run it for real.
Work on a copy
The first time a script touches a folder you care about, point it at a duplicate.

When something goes wrong

What you see
What it means
What to do
permission denied when running a script
The file is not marked as something that can be run.
Ask Claude to make it executable.
The scheduled job did not run
The Mac was asleep, or the scheduler could not find a tool the script uses.
Check the status file. If there is no line at all, ask Claude to check the schedule and the paths it uses.
It works when I run it and fails on schedule
The scheduler runs with fewer settings than your terminal.
Tell Claude exactly that. It is a well-known cause with a standard fix.
The Electron window is blank
The page inside the window has an error.
Ask Claude to open the developer tools in the window and read the error.
A friend cannot open my app
macOS blocks apps that are not signed.
Expected. Signing is the step you skipped.

End of Phase 3

You have now used every kind of tool an agent reaches for: a framework, hosting, secrets, a database, sign-in, background jobs, command-line tools, connectors, a model inside your own product, media generation, and apps that live on your machine.

So far it has been one agent, with you reading every step. Phase 4 changes that. You will write the runbook properly, split the work across agents with different roles, and decide what they are allowed to do while you are somewhere else.
