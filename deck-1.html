Notes: This is the thesis of the whole guide. Ask the room how they use AI today before advancing.
Slide 3 of 11

Same task, two ways of working

Most people use AI the first way. The second is where the work is going.

DOING

You do it, with help

Ask a chatbot for ten headlines and pick one. Pull last week’s numbers into a sheet every Monday.

DIRECTING

You get it built

A tool drafts headlines against the brief. A scheduled job pulls the numbers and sends a summary.

Notes: Module 1. Stress that the left column is not wrong. It is the smallest version. Video 1 covers this in about a minute.

Slide 6 of 11

Four words carry the guide

MODEL

A brilliant freelancer

Capable and fast, with no memory of your client or yesterday.

AGENT

The freelancer with a laptop

It can read files, run commands and keep going until done.

HARNESS

The agency around them

Written rules, roles, review, and what needs sign-off.

CONTEXT

What is on the desk

Everything the agent can see right now. The desk has a fixed size.

Notes: Module 2. The agency analogy is deliberate: students already know how an agency turns a request into finished work. Video 2 covers this.
Slide 7 of 11

Chat answers. An agent acts.

It repeats four steps until the job is done or it gets stuck.

1

Read

Looks at the request and the project’s files.

2

Plan

Decides what to change and in what order.

3

Act

Edits files and runs commands on your computer.

4

Check

Runs it, reads the result, and loops if it is wrong.

Notes: Module 2. Step 3 is why the guide spends time on permissions. An agent that can act can act wrongly.
Slide 8 of 11

The agent forgets. Files remember.

Every session starts from nothing. The fix is a plain text file it reads every time: the runbook.

Notes: Module 2. This is the idea most beginners miss. Phase 4 is built on it.
Slide 9 of 11

Why agents fail, and what fixes it

What goes wrongThe fix
Vague briefSay what done looks like, starting with “I can…”
Overloaded contextEnd the session, save a handoff, start fresh.
Confident and wrongA rule to read before asserting, and a second agent to review.
Quietly wrongMake failures loud. Unattended work must report when it breaks.
Does too muchScope rules, and gates on anything with consequences.
Notes: Module 2. Each fix is something the student controls. None requires writing code.
Slide 10 of 11

Approve consequences, not code

You do not read every line. You decide which actions need your yes.

1

Does it cost money?

A paid service, credits, a subscription.

2

Does it reach a real person?

An email, a post, a message to a client.

3

Can it be undone?

Deleting data and overwriting history cannot.

Notes: Module 2. If any answer is yes, the agent stops and asks. This grows into four tiers in Phase 4.
