MCP and connectors

Give your agent access to the places your work lives, and set the rule for what it may do there without asking.

45 minutesFree

What it is

Command-line tools cover the services developers use. Much of your working life sits elsewhere: documents, email, calendars, project boards, a CRM, a design tool. Most of those have no CLI.

MCP, the Model Context Protocol, fills that gap. It is an open standard for connecting AI applications to outside systems. Its own documentation compares it to a USB-C port: one standard plug, many devices. A company publishes an MCP server for its product, and any agent that speaks MCP can use it.

Once a server is connected, the agent can see a list of that product's tools, such as search pages, read a document or create a task, and call them while it works.

Connect your first server

1
Add a harmless one

Run this in the terminal itself, not inside a Claude session. You are configuring Claude Code before starting a conversation.

Type this
claude mcp add --transport http claude-code-docs https://code.claude.com/docs/mcp

The name claude-code-docs is one you make up. The address is where the server lives. This server gives the agent Claude Code's own documentation, and it cannot change anything.

2
Check it is there
Type this
claude mcp list
3
Use it
Type this
cd ~/Code/campaign-notes
claude
Type this to Claude
Use the docs server to explain what hooks are in Claude Code, in three sentences.

Inside a session, type /mcp at any time to see your servers and their status.

4
Add one that signs in to your account

If you use Notion, connect it. If you do not, read this step and move on.

Type this
claude mcp add --transport http notion https://mcp.notion.com/mcp

Start Claude, type /mcp, choose the server and sign in through the browser window that opens.

5
Chain it with your own tool
Type this to Claude
Read my Notion page called Fall campaign brainstorm.
List the ideas you find and wait for me to confirm.
Then add each one to Campaign Notes using notes-cli.

An agent just moved information between two systems that know nothing about each other, using a connector for one and a command you built for the other.

Reading is cheap. Writing needs a yes.

A connected server can act inside your real accounts. The safe pattern is the same one this guide has used since Module 2: let the agent look freely, and make it stop before it changes anything.

From the runbook behind this guide
Read tools: use freely as part of investigating a question. Write tools: only call after explicit user confirmation. Spell out exactly what you are about to do before doing it.
From the runbook behind this guide
Never bulk-delete or bulk-update based on a single instruction without confirming the count and scope first.
Type this to Claude
Add this to the agent instructions:
With any connected service, read freely. Before creating, changing, sending or deleting anything,
tell me exactly what will change and how many items, and wait for my yes.

Three cautions

Only connect servers you trust
Use the server published by the company whose product it is, or by a source you have a reason to trust. A server sees whatever you grant it.
What a tool returns is information, not instructions
A web page, an email or a document can contain text written to look like a command. If the agent reads something that tells it to do something you did not ask for, it should stop and tell you.
Every server takes up room on the desk
Each connection adds its list of tools to the agent's context. Connect what you use, and remove the rest with claude mcp remove and the server's name.
