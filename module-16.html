Phase 3: The stack / Module 16

OpenRouter and media generation

One key for hundreds of models. Build a small tool that makes images, speech and video, and learn what to check before any of it goes to a client.

75 minutesA few dollars of credit

What it is

Module 15 connected your app to one model from one company. There are hundreds of models from dozens of companies, and the best one for a job changes every few months. Opening an account with each provider does not scale.

OpenRouter is a single account and a single key that reaches most of them. You change one line, the model's name, to switch. It covers text models, and also the ones that produce images, video and speech.

For advertising work this is the creative lab: concept images, storyboard frames, scratch voiceover, short motion tests. Each of those is one request.

Cost: OpenRouter itself adds no subscription. You add credit and pay each model's own price. Start with the smallest amount. A still image costs cents. Video costs noticeably more. See openrouter.ai.

What you can generate

Kind
What comes back
What to know
Text
Words, or structured fields.
The same as Module 15, with many more models to choose from.
Image
A picture file.
Fast. Usually a few seconds. Models differ a lot in style and in how well they render text.
Video
A short clip.
Slow. Your code submits a job, checks on it, and downloads the result when it is ready. Run it as a background job.
Speech
An audio file of a voice reading your text.
Good enough for scratch tracks and for narration.
Transcription
Text from an audio file.
Useful for turning recordings and meetings into notes.

Do not memorize model names

Any list printed here would be out of date within weeks. Learn how to find out instead. The models page can be filtered by what a model produces, and shows each one's price.

Better still, have the agent ask. OpenRouter publishes its current catalog in a form a program can read, so the agent can list what is available today and choose by price and capability.

Build a media lab

You will build this as a command-line tool, as in Module 13, in its own folder.

1
Create an account and a key

Sign up at openrouter.ai and add a small amount of credit. Create a key, and set a credit limit on the key itself so it cannot spend more than you intend.

Type this
mkdir ~/Code/media-lab
cd ~/Code/media-lab
git init
touch .env.localni .env.local
open -e .env.localnotepad .env.local
In the file
OPENROUTER_API_KEY=paste-here
2
Have the agent build the image command
Type this to Claude
Build a command-line tool here called lab. Read OpenRouter's current image generation documentation first.
lab image "prompt" generates one image and saves it in an output folder, named with the date and time.
List the image models available right now and choose a low-cost one. Let me override it with --model.
Save a small text file next to each image recording the prompt, the model and the cost if the API reports it.
Make sure .env.local and the output folder are ignored by Git.
3
Make something
Type this
lab image "storefront poster for a neighborhood coffee shop, flat illustration, autumn colors, no text"
open outputstart output

Run it three times with small changes to the prompt. Notice how much the wording moves the result.

4
Add a voice
Type this to Claude
Add lab speak "text" that turns text into speech and saves an audio file, with the same record-keeping.
List the available speech models and voices first and show me the options.
Type this
lab speak "Second Shift Coffee. Open late, because some of us are."
5
Try one video
Type this to Claude
Add lab video that takes a prompt and makes one short clip. Tell me the estimated cost before running and wait for my yes.
It should submit the job, report progress while it waits, and download the file when ready.

Do this once, to see how it works and what it costs. Then decide how often you want to.

This guide was made this way

The narration for the videos in this guide is produced the same way. A script file with one scene per section goes to an agent, the agent calls a speech model for each scene, and the audio files come back with a list of their durations. No studio is involved.

Before you use any of it for a client

Generating an image is easy. Being allowed to use it is a separate question.

Rights
Check the model's terms
Each model has its own rules about commercial use. Read them for the model you used before the work leaves your computer.
People and brands
Do not generate what you could not license
No real people, no existing characters, no other companies' logos or trade dress.
Disclosure
Follow the client's policy
Many agencies and clients have rules about AI-generated work. Ask before you present it, not after.
Records
Keep the receipt
The small text file beside each asset is your record of what made it. You will be asked.
From the runbook behind this guide
Generated imagery only from models whose terms allow commercial use, and say which.

Set a spending rule and write it down

An agent in a loop can generate a great deal of media very quickly. The key's credit limit is the hard stop. A rule in the runbook is the soft one.

Type this to Claude
Add to the agent instructions for media-lab:
No more than 2 dollars of generation in one run and 5 in one day without asking me.
Always state the estimated cost before any video generation.

When something goes wrong

What you see
What it means
What to do
402, or insufficient credits
The account or the key has reached its limit.
Check which. Raise the key's limit or add credit, on purpose.
Model not found, or unsupported option
The model's name changed, or it does not accept that setting.
Ask Claude to list current models and their supported options.
The video never arrives
The job is still running, or it failed quietly.
Ask Claude to check the job's status and report any error it returned.
The request was refused
The prompt broke the model's content rules.
Reword it. If it involved a real person or a brand, that is why.
Text in the image is garbled
Many image models are poor at lettering.
Ask for no text, and add type yourself in a design tool.
