Slide 5 of 14

Secrets: names in code, values somewhere else

A leaked key is the most common serious beginner mistake. It takes seconds.

SAFE TO SHARE

The name

DATABASE_URL appears in code and on GitHub. It says which secret is needed, not what it is.

NEVER SHARED

The value

Lives in a local file Git ignores, and in the host’s settings. Not in code, not in Git, not in a chat.

Notes: Module 9. Taught before the database on purpose. Students practice with a harmless value and watch the live site go blank until they add it to the host.
Slide 6 of 14

Enough SQL to read a query

A database is a spreadsheet the app can read and write.

StatementWhat it does
SELECTRead rows.
WHEREChoose which rows.
INSERTAdd a row.
UPDATEChange rows. Without WHERE, every row.
DELETERemove rows. Without WHERE, every row.
Notes: Module 10. The agent writes SQL. The student must recognize what a statement will do before approving it. Find the WHERE.

Slide 10 of 14

Agent or pipeline?

Module 15 puts a model inside the student’s own app.

AGENT

You give a goal

It decides its own steps. Flexible, good for building. Harder to predict and to test.

PIPELINE

You define the steps

A model does each one. Predictable, testable, cheaper. Right for work that repeats.

Notes: Module 15. The author’s production systems are pipelines. Use an agent to build the pipeline, and the pipeline for the repeated work. Video 6.

Before generated media goes to a client

Module 16: one key, many models. Images, video, speech.

RIGHTS

Check the model’s terms

Commercial use differs by model.

PEOPLE

No real people or brands

Nothing you could not license.

DISCLOSURE

Follow client policy

Ask before you present it.

RECORDS

Keep the receipt

Prompt, model and date, beside each asset.

Notes: Module 16. One key reaches image, video, speech and transcription models. Generating is easy. Being allowed to use it is a separate question.
