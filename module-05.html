Phase 2: Setup / Module 05

Git and GitHub

Your save button and your undo button. Set these up before an agent touches anything you care about.

45 minutesFree

What they are

Git keeps a history of your project as a series of save points. Think of version history in Google Docs, with one difference: you decide when to save, and you label each save with a short note about what changed.

GitHub is a website that stores a copy of that history online. It is your backup, and it is also where hosting services pick up your code to put it on the internet. Git is the tool on your computer. GitHub is the place your project lives in the cloud.

Why you need it before you let an agent loose

An agent can change twenty files in a minute. Most of the time that is what you want. Sometimes it is not, and without save points you have no way back.

With Git, the habit is simple. Save before the agent does anything big. If you like the result, save again. If you do not, go back. This one habit removes most of the fear from working with agents.

Save 1
First version of the page
Monday
Save 2
Add the contact form
Tuesday
Save 3
Change the colors
Tuesday night
Save 4
Agent rewrites the layout
Wednesday

If save 4 turns out to be a mistake, you return to save 3 and nothing is lost. Each save is called a commit.

Git as save points

Eight words you will hear constantly

Word
Meaning
repository (repo)
A project folder that Git is tracking.
commit
One save point, with a note describing what changed.
push
Send your new commits from your computer up to GitHub.
pull
Bring down commits from GitHub that your computer does not have yet.
clone
Download a full copy of a repository from GitHub.
branch
A parallel copy of the project where you can try something without touching the main version.
main
The name of the primary branch. For many hosted apps, what is on main is what is live.
pull request (PR)
A proposal to merge one branch into another, with a place to review the changes first.

Set it up

1
Create a GitHub account

Sign up at github.com. Use the same personal email as your Claude account. The free plan is all you need.

2
Check that Git is installed
Type this
git --version
You should see: a version number. Installing Homebrew in Module 4 also installed Git. If your Mac offers to install developer tools, accept.
3
Tell Git who you are

Every commit is stamped with a name and email. Use the email on your GitHub account.

Type this
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
4
Install the GitHub command-line tool and sign in
Type this
brew install gh
gh auth login

Choose GitHub.com when asked, then follow the prompts. A browser window opens for you to approve the sign-in.

5
Make your first commit

Go to the practice folder from Module 4 and turn it into a repository.

Type this
cd ~/Code/first-project
git init
git add .
git commit -m "First save"
You should see: a line mentioning 1 file changed, or similar.
6
Put it on GitHub
Type this
gh repo create first-project --private --source=. --push
You should see: a link to your new repository. Open github.com and find it under your profile.

The loop you will repeat

Once a project is set up, saving your work is always the same four steps.

Command
What it does
git status
Shows which files changed since the last commit.
git add .
Marks all of those changes to go into the next commit.
git commit -m "note"
Creates the save point with your note.
git push
Sends it to GitHub.

In practice you will usually ask the agent to do this by typing something like: commit my changes with a descriptive message. That works well. You still need to know the four steps, because you are the one approving them.

Two rules from day one

Keep repositories private
The command above creates a private repository, which only you can see. Leave it that way unless you have a reason to publish.
Never commit a password or API key
Anything committed to Git stays in its history, even after you delete the file. Module 12 shows where secrets go instead.

When something goes wrong

What you see
What it means
What to do
not a git repository
You are not inside a project folder, or the folder has not been set up with Git.
Run pwd. Move into the project, or run git init if it is new.
Author identity unknown
Git does not know your name and email.
Run the two git config commands from the setup steps.
nothing to commit
No files have changed since the last commit.
Nothing is wrong. There is nothing new to save.
rejected, or failed to push
GitHub has commits your computer does not have.
Run git pull and then push again. If that fails, paste the error to Claude.
Anything else
Git errors are famously unfriendly.
Copy the whole message and ask Claude what it means and how to fix it safely.
